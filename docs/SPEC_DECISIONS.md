# 原文要求、实现选择与待确认项

依据：用户上传《UDP 多模块实时数据传输协议》（UDP协议.docx / UDP协议(1).docx）。未擅自新增线上包类型或字段。

| 项目 | 本版行为 | 性质 |
|---|---|---|
| DATA/NACK、LE、magic、32B头/4BCRC、1436B步长 | 按说明书固定实现，界面不能修改 | 原文要求 |
| 20ms周期、15ms首轮窗口 | 绝对时间计划及超期统计，尚需目标硬件验证 | 实现目标，非硬实时保证 |
| 最近3帧，logic_id%3 | 默认严格照原文 | 原文要求；回绕点有已知缺陷 |
| FIFO三槽 | 用户明确选用后才启用，线上字段不变 | 候选勘误；不是默认兼容模式 |
| 模块体格式 | 不透明仿真字节或原始文件，不定义医疗业务编码 | 原文未定义业务数据体 |
| TS来源 | 明确标注主机单调计数器模拟TS | 与真实外部硬件采样的差距 |
| 全模块离线 | 跳过该采样、不分配新logic_id、不发零长度帧 | 原文未定义；本地选择 |
| 超过2MiB | 本采样计为buildRejected，不发数据，后续采样继续 | 原文要求 |
| logic_id分配 | 成功组帧后递增，失败/全离线不消耗 | 按第3节流程选择；与“每采样加1”措辞需确认 |
| 同进程停止重开 | GUI保存next_logic_id；重新启动接收端状态仍需约定 | 原文未定义会话重启规则 |
| 同片重复NACK | 当前待发任务可合并；任务发出后重新请求仍有效 | 不使用不存在的requestId，不拒绝合法后续请求 |
| 超过3次请求 | Sim不终止流；接收测试桩执行3轮规则 | 3轮计数属于接收端，原文未给发送端轮次字段 |
| NACK来源端口 | 默认不限，来源IP默认与目标相同，可独立配置 | 文档只明确NACK目的端点 |
| 发送过载 | 记录超期/未发片，旧帧不阻止新采样；不修改协议字段 | 实现降级政策，不能算性能通过 |
| 有限帧测试结束 | 本地保留60ms补发收尾后停止，无FIN/CANCEL | 开发测试行为，不是线上控制协议 |

## 回绕缓存问题

`0xFFFFFFFF % 3 == 0` 且 `0 % 3 == 0`，默认原文模式在此处会提前覆盖上一帧。核心测试明确保存这个行为作为文档兼容性测试，而不是伪称已解决。
`--cache-policy fifo` / GUI“候选勘误：FIFO三帧”使用独立写指针和完整logic_id查找，保持真正最近三帧。正式项目采用前应记录双方确认。

## 带宽矛盾

2MiB仅数据位数/1Gbps约16.78ms；加上报头及常规以太网间隙约17.97ms。默认链路可行性检查因此拒绝2MiB+1000Mbit/s+15ms组合。
1MiB估算约8.99ms，可在15ms窗口内留出一定余量，但不表示本机程序、接收端和网卡一定达标。
链路估算未包含VLAN、隧道等额外开销，不自动检测实际网卡速率。用户选择2.5Gbps不等于硬件真的升级。

## 接收端缓冲与重启

原文20ms接收缓冲与最坏约47ms补片完成的关系，需要正式接收平台明确。此项目不实现接收端渲染；测试桩只做有界重组、计时、NACK和本地完成统计。
没有session字段；旧报文与进程重启后复用logic_id可能混淆。重启联调建议同时重启/清空测试接收端，不在报头私加字段。

## 安全与准确性

CRC32用于误码检测，不验证发送者身份。来源IP/端口过滤不是加密认证。本工具没有实现公网拥塞控制、DTLS、HMAC或者医疗产品安全认证。
