# SimTransferRT 0.3.2 发布说明

**2026-11-26 · Windows x64 Release**

上一候选在 600 秒本机环回中收齐了两路共 66,000 帧，发包抖动和完整首发均达标。NDI、EP 的 Qt 控件更新仍有超期。0.3.2 在此后加入了波形缓存和界面峰值的页面状态记录。本次发布保留这两项已知问题，最终二进制的 600 秒验收待完成。

## 上一候选的 600 秒环回结果

测试使用可见 GUI 和 `127.0.0.1`，关闭分片追踪及故障注入，使用 1 GbE 配置。模拟 NDI 为 4 个工具、60 Hz，EP 为每帧 204,800 字节、50 Hz。正式测试于 2026-11-26 07:23:54 UTC 启动，测试驱动 SHA-256 前 12 位为 `9f629d13e7c5`。

| --- | ---: | ---: | --- |
| 构建 / 完整接收 / 消费 | 36,000 / 36,000 / 36,000 帧 | 30,000 / 30,000 / 30,000 帧 | 两路数量及帧摘要核对通过 |

**全流发包间隔偏差峰值为 428 µs，4,325,999 个相邻间隔均达标。** 分模块统计各自的首发数据包，全流按实际发送次序跨模块统计。两者均比较本机开始发送的相邻间隔与原调度计划间隔。完整首发从采样时刻计至该帧所有初始分片的本地成功完成回调。界面计时止于控件数据更新。物理网卡出线、屏幕呈现和真实设备时钟同步仍需独立测量。本轮未产生 NACK，重传轮次时序也需另测。

## 主要改动

- **Asio 收发与调度。** 发送端使用有界槽位跟踪异步完成，以回调时间结算完整首发。运行中尚在途的帧保留待判状态，收尾后逐帧核对。采样线程默认经有界单生产者、单消费者队列向发送线程交接，Windows 接收端可同时等待套接字可读事件和高精度定时器。上一候选测得上述结果时，NDI 交接提前量为 0 µs，Asio 回调内存复用关闭。
- **Qt 接收页与三维预览。** 高优先级 Qt 事件可一次唤醒多个待处理帧，控件仍逐帧更新并计时。发送页、报告页和预览的刷新考虑当前可见状态。本次 x64 Release 与上一候选都显式启用了 `SIM_GUI_IMMEDIATE_SWAP=ON`，常规 CMake 配置默认关闭。上一候选请求交换间隔 0，顶层窗口报告 0，VTK 控件上下文报告 1。
- **静态背景。** 按控件尺寸及设备像素比缓存一张背景图，上限 32 MiB。尺寸或缩放变化后，小脏区继续按原路径绘制，待较大区域需要刷新时再生成缓存。
- **EP 波形。** 仅在连续两帧的显示采样逐点相同时跳过波形控件主动重绘。新值第一次直接绘制，重复数据后遇到合适的完整重绘才建立像素缓存，上限 8 MiB。帧号、状态标签和逐帧计时继续更新。Windows Qt 隐藏窗口控件试验中，16 帧相同采样触发 0 次主动绘制，16 帧变化采样触发 16 次。12 次被动重绘均命中缓存。100%、125%、150%、200% 缩放下每档 32 组像素对照均一致。
- **峰值诊断。** 正式报告为两路界面峰值保留帧号、时间和当时的页面、可见及最小化状态。可选慢帧追踪进一步关联 GUI 排队、控件绘制和 Qt 合成，便于复查长测中的尾部延迟。

## 复现本版环回验收

从源码构建时，在项目的 x64 Release 配置中启用 `SIM_WITH_ASIO`、`SIM_MODEL_PREVIEW`、`SIM_BUILD_TESTS` 和 `SIM_GUI_IMMEDIATE_SWAP`。在普通 PowerShell 中从仓库根目录执行以下命令，保持接收页可见。`--build` 指向包含 `SimAppMemoryTests.exe` 及 `CMakeCache.txt` 的构建目录。脚本先运行基础测试，再运行关闭追踪的正式长测，并生成 `run.json` 和收发联合报告 `joint.json`。

```powershell
py -3 -B tools/run_release_loopback.py --build build/release-0.3.2/Release --basic-tests --visible --seconds 600 --ndi-handoff-guard-us 0
```
