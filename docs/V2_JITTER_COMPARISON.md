# V2 Release 传输抖动对比

本次对比使用 `dev` 的 V2 双模块发送路径。基线为 `802f7802e0b45b46474e966fa6f83ad8452316ca`，优化版代码提交为 `6fa50d102f8c19e77702327e8b62fdde28cd70e2`。发送端使用 `SimTransferCli.exe` 的 Qt `QUdpSocket`，接收端使用独立进程运行同一份 [Python V2 接收桩](../tools/v2_receiver.py)。

## 负载与测试顺序

| 条件 | 设置 |
| --- | --- |

本机回环实测覆盖采样、组帧、主机发送调度、UDP 提交及接收桩重组。物理网卡出线、交换网络、真实采集设备与 Qt 接收界面需要各自的测量。

## 毫秒级抖动如何定位

先用基线跑 15 秒。EP 构建 750 帧，首发超期 0 次，组帧准备最长 4,777 µs。同模块相邻首发包的间隔偏差最大达到 4,739 µs。以保留的最差包记录中的 EP 第 173 帧为例，从实际采样到组帧就绪用了 4,561 µs。其第 725 号分片从原始计划到实际开始发送晚了 8,090 µs，从调整后允许发送的时刻到实际开始只差 13 µs。两套时刻共同保留了此前累积的延迟和当前包的调度偏差。该轮 EP 首发耗时上限为 17,018 µs，仍在 18 ms 时限内。

另用独立的 30 秒诊断版观察发送线程的队列、状态、快照与链路观测锁。发送线程共有 84 次 `try_lock` 失败，从记录失败到成功取得锁，最长 5 µs。其中 22 次在试锁前后观察到同一代次、同一其他线程持有锁，这一子集相应的最长耗时为 1 µs。用同一单调时钟把保留的锁事件与保留的迟发包窗口（调整后的允许发送时刻至实际开始发送）对齐，重叠数为 0。

探针记录到一次 1,067 µs 的取锁过程总耗时，起点在尝试取得锁之前，这段时间也可能包含线程被抢占。试锁允许偶发失败，探针自身有开销，事件明细采用有限长度记录，CLI 也没有持续轮询状态的 GUI 读者。当前记录表明，组帧消耗了毫秒级时间。锁探针尚未观察到能解释该尾延迟的锁争用，因此保留原有同步机制。

原版随后在 30 分钟长测中出现 9 次 EP 首发超期。最慢的是第 10,207 帧，从实际采样到组帧就绪为 3.395 ms，等待第一次发送为 0.128 ms，首片开始到末片返回为 16.881 ms，合计 20.404 ms。另有一帧准备耗时 7.898 ms，一帧从就绪到首片开始用了 4.039 ms。这些记录既支持优化准备阶段，也显示了就绪后仍存在的延迟。

## 改动

1. EP 模拟源和文件回放源在会话内各自重复使用固定内容。在首次采样前一次性生成分片模板，计算业务载荷及各个分片的 CRC。后续每帧拥有独立的帧号和采样时间戳。完整分片长度相同，尾片可能较短，分别计算两种长度所需的 CRC 修正值。发送时复制当前分片，在这份局部数据上写入帧号、时间戳和校验值。缓存中的旧帧保留自己的身份信息，重传包按原规则设置标记并校验。动态 NDI 每次仍从当次采集的实际字节组帧。
2. 会话在锁外构造只读状态快照，加锁交换共享指针。读者取得指针后在锁外生成报告，旧快照在锁外释放。Qt 接收线程与界面交换待展示的快照时也将旧帧的释放移到锁外。Qt 命令行发送程序与独立 Python 接收桩覆盖第一项改动和发送端快照发布成本。Qt 窗口的刷新、停启与关闭属于单独的界面验证范围。

## 指标口径

| 指标 | 计算与判读 |
| --- | --- |
| 首发超期次数 | 发送端 `deadline_misses`。从该帧实际采样时刻到最后一次首发调用返回，EP 超过 18,000 µs、NDI 超过 15,000 µs 记一次。另列 `initial_incomplete`（首次提交未完成），避免漏掉未走完全部分片的帧。 |
| 首发耗时 | `initial_duration`，仅统计全部分片首次本地提交成功的帧。EP 优化后的 `ready_us` 表示模板、帧元数据及 CRC 修正值已就绪，发送时写入分片头的开销仍在“采样到最后一次首发返回”区间内。 |
| 采样周期抖动 | 每个模块分别统计相邻实际采样间隔与其名义周期的绝对差，对应 `sampling_deviation`。EP 名义周期 20,000 µs，NDI 使用取整后的 16,667 µs。 |
| 首发包间隔抖动 | 对该模块相邻两次原始分片提交，取“实际发送开始间隔”与这对分片在原始全局计划中的间隔之差的绝对值，对应 `packet_gap_deviation`。工程目标严格小于 1,000 µs。 |
| P99.9 与最大值 | `p999_us` 基于整轮全部观测值的 100 µs 分桶，返回分位所在桶的上限，并以实测最大值为上限。最大值 `max_us` 直接取实测值。多轮分别列出 P99.9，跨轮取极值可按各轮最大值再取最大。 |
| 接收完整率 | 按模块用接收端 `completed` 除以同轮发送端 `built`，保留帧数分子和分母。另查 `skipped_slots` 和 `queue_drops`。被跳过的采样不进入已构建分母。用同一运行 ID 核对双方帧数、帧号和、载荷 CRC 和、时间戳和，并检查业务错误及已消费帧数。 |

## 实测对比

交错运行的三轮 120 秒短测中，每个版本均收到 EP 18,000/18,000 帧、NDI 21,600/21,600 帧。首发超期、首发未完成和跳采均为零。EP 首发耗时 P99.9 从各轮 15.3–15.8 ms 降至 12.2–12.5 ms，NDI 包间隔抖动 P99.9 从 4.8–5.4 ms 降至 2.2–3.3 ms。EP 包间隔抖动 P99.9 原版各轮均为 0.2 ms，优化后三轮为 0.2、0.2、0.3 ms。短测中 EP 采样抖动的最大值由 1.805 ms 升至 2.521 ms。

优化版 Debug 和 Release 的 CTest 各通过 12/12 项，Python 单元测试通过 188/188 项。三档带宽的 V2 功能矩阵通过 50/50 个场景，包括多片 NDI、EP 的边界长度、丢片补传、CRC 损坏、帧号回绕、双端口和回放。跨语言协议检查覆盖 30 个 Python 生成的有效向量、14 个无效向量和 4 个从 C++ 回读的向量。独立 Release 分发目录通过 GUI 冒烟测试。清除 Qt SDK 的 PATH 后，包内 CLI 使用随包部署的 Qt DLL 完成 3 秒回环，NDI 收齐 180/180 帧，EP 收齐 150/150 帧。这项打包检查使用默认 200 KiB EP 载荷。

**30 分钟对照中，组帧成本和首发耗时 P99.9 下降，首发超期次数及最大抖动上升。** EP 逐帧准备的最大耗时从 7.898 ms 降至 0.695 ms，首发耗时 P99.9 从 15.5 ms 降至 12.2 ms，降幅约 21%。EP 首发超期从 9 次升至 15 次，NDI 从 0 次升至 1 次。两路已构建帧都完整到达，收发摘要一致。EP 被跳过的采样机会从 19 次升至 90 次，NDI 从 25 次升至 127 次，两组的发送队列丢帧均为 0。按理论采样机会计算，EP 交付 89,981/90,000 与 89,910/90,000 帧，NDI 交付 107,975/108,000 与 107,873/108,000 帧。

优化版的 15 个 EP 超期事件全部留有记录。准备用了 2–11 µs，从帧就绪到开始发首片等待了 7.644–9.639 ms。最慢的第 9,863 帧用了 0.009 ms 准备、9.639 ms 等待、12.429 ms 完成首轮发送，共 22.077 ms。唯一超期的 NDI 帧从就绪到发首片等了 16.492 ms。EP 的包间隔抖动 P99.9 在两轮长测中均为 0.2 ms，最大值却从 72.521 ms 升到 81.583 ms。NDI 的包间隔 P99.9 由 5.4 ms 降至 3.5 ms，最大值同样上升。

两轮长测依次运行，每个版本各一个 30 分钟样本。最坏值反映该时段主机上实际发生的停顿。当前计时足以把优化后超期帧的等待定位到就绪之后，进一步区分唤醒、线程获调度及两路发送排队各占多少，需要对应时段的调度记录。两份长测均通过功能校验，均未达到全部严格时序指标。

## 在 PowerShell 中复现

在优化版仓库根目录运行以下两段命令。需要 Git、CMake、Python 3、MSVC v143 14.44 和对应的 Qt MSVC x64 SDK。构建脚本读取 `QT_PREFIX` 和 `VS_BUILD_TOOLS`，示例在变量尚未设置时询问本机安装目录。两组共用同一个 Python 解释器、接收桩和 Qt 运行库。

```powershell
$ErrorActionPreference = 'Stop'
$candidate = (git rev-parse --show-toplevel).Trim()
$tag = [guid]::NewGuid().ToString('N')
$baseline = Join-Path ([IO.Path]::GetTempPath()) "simrt-v2-base-$tag"
$results = Join-Path $candidate "artifacts/udp-stability/v2-comparison-$tag"
if (-not $env:QT_PREFIX) { $env:QT_PREFIX = Read-Host 'Qt MSVC x64 SDK 目录' }
if (-not $env:VS_BUILD_TOOLS) { $env:VS_BUILD_TOOLS = Read-Host 'Visual Studio Build Tools 安装目录' }
$env:PATH = (Join-Path $env:QT_PREFIX 'bin') + [IO.Path]::PathSeparator + $env:PATH
git worktree add --detach $baseline 802f780
if ($LASTEXITCODE -ne 0) { throw '创建基线工作区失败' }
foreach ($tree in $baseline, $candidate) {
    & (Join-Path $tree 'scripts/build.cmd') Release
    if ($LASTEXITCODE -ne 0) { throw "Release 构建或测试失败 $tree" }
}
```

下面直接调用仓库 [run_case](../tools/run_v2_validation.py)，逐轮分配端口，记录命令及程序哈希，等接收桩就绪后再计时。显式传入的 1 MiB 和 4 个工具会覆盖脚本的通用默认负载。每轮结束后可从 `sender.json` 的 `config` 核对实际生效的值。

```powershell
@'
import sys
from pathlib import Path

baseline, candidate, results = map(Path, sys.argv[1:])
sys.path.insert(0, str(candidate / "tools"))
from run_v2_validation import run_case

cli = Path("build/windows-release/SimTransferCli.exe")
options = ["--ep-bytes", "1048576", "--ep-hz", "50",
           "--ndi-tools", "4", "--ndi-hz", "60",
           "--ndi-phase-us", "0", "--ep-phase-us", "0",
           "--target", "127.0.0.1", "--bind", "127.0.0.1",
           "--status-interval-us", "0"]
trials = [("before", 120), ("after", 120), ("after", 120), ("before", 120),
          ("before", 120), ("after", 120), ("before", 1800), ("after", 1800)]
failed = []
for i, (version, seconds) in enumerate(trials, start=1):
    name = f"{i:02d}-{version}"
    sender = (baseline if version == "before" else candidate) / cli
    result = run_case(sender, results, name, "1g", seconds=seconds, extra=options)
    if not result["functional_pass"]:
        failed.append(name)
if failed:
    raise SystemExit("Functional check failed in: " + ", ".join(failed))
'@ | python -X utf8 - $baseline $candidate $results
if ($LASTEXITCODE -ne 0) { throw "请检查各轮日志 $results" }
Get-ChildItem -LiteralPath $results -Directory
```

每轮目录内，`commands.json` 记录实际调用与哈希，`sender.json` 记录发送时序和计数，`receiver.json` 记录完整帧和业务消费，`acceptance.json` 保存联合验收，`result.json` 记录进程退出和功能校验。即使收发数量和校验汇总完全匹配，仍要单独核对首发超期、跳采及包间隔抖动。
