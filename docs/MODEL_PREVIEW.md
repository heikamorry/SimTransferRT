# 本地三维预览与文件转换

启动 Windows 分发目录里的 `bin\SimTransfer.exe`，进入 **接收与显示**。左侧保留实时接收表，右侧可独立打开本机文件。拖动中间分隔条可调整宽度，下次启动沿用上次设置。打开文件无需启动发送或接收。

窗口采用医疗数据链路主题：浅色临床渐变背景、阿斯克勒庇俄斯之杖水印和心电图基线，仅作视觉标识，不参与测量。右侧工具栏以 **打开 ▾** 为主操作，模型、BX 帧序列和过程档案在同一菜单；**转换 / 另存为** 为次操作，**取消** 只在任务期间可用，**重置视图** 靠右放置。点云可用 **点大小** 调整显示尺寸，该设置只影响本地渲染。BX 只做校验、解码和点云预览；不显示工具表，也不提供反向模型导出。

## 打开和查看

1. 在右侧点 **打开 ▾ → 打开模型**，选择 PLY、VTP 或 legacy VTK。文件名可任意，程序检查文件签名、格式头、字段、长度和索引。也可以从命令行运行 `SimTransfer.exe --model "D:\models\example.vtp"`。
2. 拖动鼠标左键旋转，中键平移，滚轮缩放。点 **重置视图** 重新取景。在 **表面 / 点云 / 线框** 间切换。无面连接的模型按点显示。
3. 属性框默认选 **原始颜色**。可以选择统一颜色或按数值属性着色。含多个分量的伪彩显示使用第一个分量。面板列出点数、单元数、属性数、单位和坐标系。缺少坐标约定或单位时显示“未知”。**详情** 可查看字段名称、关联、数值类型、分量数和元组数。显示时隐藏无效坐标及使用它们的单元，原始数组仍用于转换。
4. 用 **打开 ▾ → 打开 NDI/BX 文件** 读取 Aurora BX 帧序列。程序逐帧校验起始标记、声明长度、头/正文 CRC16 和工具记录边界，按帧顺序、帧内工具记录顺序收集全部 Valid 位置，构建点云并自动适配相机。面板显示帧数、有效位置数、Missing/Disabled 计数、点云记录数和坐标范围（mm）。
   - 重复 Handle、重复坐标和 UInt32 帧号回绕不会合并或删除样本；同一 Handle 的连续帧会产生多条位置记录。
   - Missing 和 Disabled 只计入状态统计，不产生 `(0,0,0)` 之类的虚假坐标。
   - 单帧应答和多帧连续字节流走同一个解码器。CRC 错误、截断、非法长度或非有限坐标会报告文件偏移和原因。
   - BX 的 Float32 位置可精确提升到 double 用于内存处理，但这不表示恢复了源模型被舍去的 Float64 精度。

## 模型导出为 BX

1. 先加载 PLY、VTP 或 legacy VTK 模型。点 **转换 / 另存为**，选择 **Aurora BX (*.bx)**，输入新文件名。
2. 能力检查会列出输入点数、输出帧数、单位映射、Float32 舍入规则和省略的属性。每个顶点生成一个单工具响应帧：`Handle 0x0A`、`HandleStatus 0x01`、`Q=(1,0,0,0)`、`IndicatorValue 0`、`PortHandleStatus 0x31`、`FrameNumber` 从 8 起每帧加 8、`SystemStatus 0`。颜色、面连接、纹理、法向和 BX 无对应字段的属性不写入。
3. 源单位明确时换算为毫米；源单位未知时采用仿真默认比例 **1 模型单位 = 1 mm**，摘要会明确标注该假设。坐标不居中、不归一化、不镜像。
4. 程序写临时文件，逐帧回读校验 53 字节布局、头/正文 CRC、固定工具字段和 Float32 位置，再提交文件并写入 HDF5 过程档案。取消或失败不会留下冒充成功的目标文件。
5. 转换摘要显示输入点数、输出帧数、字节数、最大 Float32 舍入误差、是否采用仿真单位假设以及已省略属性。生成的文件可用 **打开 ▾ → 打开 NDI/BX 文件** 再次加载，看到的就是实际 BX 解码出的点云。

## 过程档案与反向导出

1. 可先在 **打开 ▾ → 选择过程档案目录…** 指定可写目录。默认位于 Qt 用户本地应用数据目录的 `model-conversions` 子目录。
2. 选择 HDF5 作为目标时，目标文件本身兼作过程档案；模型和 BX 点云都可归档。成功后可从 **打开 ▾ → 打开输出所在目录 / 打开档案所在目录** 查找文件。每次转换生成独立任务 ID。
3. 能力检查拒绝时，点 **保存拒绝记录**，可将原因和已加载的完整源数据保存到档案。选择 **打开 ▾ → 打开过程档案** 可再次浏览源数据，在 **详情** 查看上次任务状态。
4. **BX 不支持反向导出为 PLY、VTP、legacy VTK 或另一个 BX。** 已加载的 BX 点云只提供 HDF5 过程档案；界面不提供模型目标，后端能力检查和转换入口也会拒绝。程序不恢复或伪造颜色、面连接、纹理、法向等原模型属性。
5. 处理期间可点 **取消**。进入最终提交阶段后会完成已校验文件的重命名。取消转换后，程序还需要写入取消记录和源数据，大模型可能继续占用磁盘一段时间。**打开 ▾ → 卸载当前文件** 可清空右侧视图。

## 报错后如何处理

| 看到的情况 | 原因与处理 |
|---|---|
| 无法识别、头部不完整、声明长度与文件不符、无效索引、CRC 错误 | 打开“详情”查看具体文件和字段。重新取得完整输入。打开阶段未取得完整数据集时无法生成含完整源数据的转换档案。 |
| BX 起始标记、长度、头/正文 CRC 或工具记录不符 | 报错包含文件偏移。确认文件是标准 Aurora BX 帧序列；不要把私有头、文本命令或额外分隔符混入。历史 `.bx` 若来自其他封装，需要先确认其布局。 |
| BX 文件没有有效位置 | 加载成功但点云为空；Missing/Disabled 只计数。检查工具状态和文件内容，不要把它当作已恢复的模型。 |
| 模型转 BX 提示非有限坐标、Float32 溢出或没有可用点 | 报错给出点索引和分量。修正源数据或选择其他目标；程序不会静默跳点、夹紧或补零。 |
| 能力检查列出无法表达的单元、Piece、字段类型或外部贴图 | 保留原文件，选择 HDF5，或选择矩阵内可表达这些字段的目标。不同模型即使扩展名相同，可用的目标也会不同。 |
| 未知 HDF5 版本、类型或 SHA-256 不符 | 选择受支持的 SimTransferRT 档案或从原始数据重新导出。普通 HDF5 文件需要相应领域的数据布局才能解释。 |
| 输出已存在、目录不可写、空间不足、写入或回读失败 | 用新文件名，检查目标与档案目录的空间和写权限，再重试。详情会显示失败阶段。档案目录自身不可写时也会显示档案未保存原因。 |
| 目标已发布，档案提交失败 | 详情记录已发布目标的路径。检查档案目录，使用新目标名重试，并核对有相同输出 SHA-256 的成功记录。 |
| 启动时提示无法初始化 Qt platform plugin | 完整保留分发目录及 `bin\qt.conf`、`plugins\platforms\qwindows.dll`。开发用构建目录应包含同配置的 Qt DLL 和平台插件，Debug 使用 `qwindowsd.dll`。按[构建验证](MODEL_VERIFICATION.md)重新构建缺失的产物。 |
