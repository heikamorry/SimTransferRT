# 2026-11-16 文件变更与功能说明

本次提交汇总Windows UDP测试桩修复、NACK诊断、发送稳定性优化和统一验收报告三轮工作。协议DATA/NACK格式、CRC、20ms采样目标、15ms首发目标及默认三槽缓存规则保留；没有把接收测试桩升级为生产渲染系统，也没有宣称硬实时达标。

## 修复与优化内容

1. **Windows UDP运行与报告可靠性**：分别处理接收/发送10054、10040和would-block，配置SIO_UDP_CONNRESET；不可恢复异常保留错误并非零退出，清理后仍尝试保存最终报告。可选checkpoint替换失败计数、限频后继续，最终报告写入失败仍视为失败。
2. **接收重组和NACK状态**：防止已完成或已作废旧帧重新激活；用有界重放状态、待处理帧和计时队列减少重复扫描。保持每片独立10ms请求计时、最多三次及最终等待规则，保留区间合并、乱序、重复、回绕及flags=0补回语义。
3. **发送稳定性与生命周期**：限制单轮反馈/命令处理预算；固定三份分片状态，减少逐包字符串和每帧map操作。详细快照避开首发及临近采样时刻，拥塞时发轻量心跳；快照在锁外构造并交换不可变引用。原生CLI停止信号不再依赖快照发布。
4. **可核对的计时和计数**：区分真实发送完成与旧tick入口统计；增加首发未完成/未发片守恒、P99.9、有界异常窗口、采样偏差≥1000µs计数、帧内首发片间隔及其偏差、补发和全部send调用间隔。复用已有时间戳，采用固定容量直方图；没有新增逐包日志或线上字段。
5. **接收重试时序**：新增13类有界直方图、明确的帧/片观察分母、128条最近事件环，每事件最多8片明细。分别观测发现、请求、补回、作废，缺少样本用null/未检测表示，不把零次请求当作时序通过。
6. **统一验收报告**：GUI保留JSON导出并增加Markdown六列表格；CLI使用相同本地验收逻辑。诊断脚本生成收发联合JSON/Markdown，重新核对原始帧清单、run_id和退出状态。每项列出要求、测量口径、阈值、实测值、通过/失败/未检测及原因，硬件、物理链路和渲染缺证据时不伪造通过。
7. **构建与回归**：修复本地化MSVC showIncludes导致的NMake头文件依赖遗漏；扩充确定性时钟、接收异常、生命周期、回绕、故障注入、验收防误判及GUI导出测试。

## 复现入口

```powershell
cmd /d /c scripts\build.cmd Release
cmd /d /c scripts\build.cmd Debug
cmd /d /c scripts\test-network.cmd Release
cmd /d /c scripts\test-network.cmd Debug
python tools\run_diagnostics.py --cases A1,B1,C,CRC --seconds 10 --out artifacts\udp-stability\acceptance-check
python tools\run_diagnostics.py --cases A1 --seconds 120 --out artifacts\udp-stability\acceptance-120s
```

GUI导出时选择JSON或“验收表 (*.md)”。联合诊断每个场景保存`sender-report.json`、`receiver-report.json`、`summary.json`、`acceptance.json`和`acceptance.md`。详细测量定义见[统一验收表说明](UDP_ACCEPTANCE_2026-11-16.md)。
