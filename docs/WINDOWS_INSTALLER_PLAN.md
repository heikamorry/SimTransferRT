# SimTransferRT Windows 安装包与验证记录

0.3.0 交付一个可离线使用的 Windows x64 安装文件 `dist\SimTransferRT-0.3.0-x64-Setup.exe`。用户可以选择安装目录、组件和快捷方式。再次打开同一版本的 EXE 会进入中文的「修改、修复、卸载」维护页。本次按约定使用 WiX 5.0.2 生成未签名测试包。

| 内嵌 Microsoft Visual C++ x64 运行库 14.52.37029.0 | 18,863,624 字节 | `9c02c9ed120f671b900e6b9471d890e3b2414117a7e53f4ae2e855466fa2b7c9` |

两个内嵌文件均从最终 EXE 解包并与构建输入逐字节校验，微软运行库的 Authenticode 签名有效。该 Release 的 11 项 CTest 均通过。在仅保留系统搜索路径的独立进程中，打开 PLY 模型并生成截图，实际加载的 72 个 Qt、VTK、HDF5 库和平台插件均来自发布目录。

### 2026-11-25 Windows 11 x64 实装结果

| 操作 | 观察到的结果 |
|---|---|
| 首次安装 | 用最终 EXE 的「更改」按钮打开目录选择窗口，选中 D 盘含中文和空格的测试目录。程序和开始菜单入口安装成功。桌面快捷方式和命令行工具默认关闭，系统「已安装的应用」仅有一项 SimTransferRT。 |
| 修改 | 重开同版 EXE，维护页显示实际路径及「修改、修复、卸载」三个按钮。从「修改」中勾选或取消两个选项，对应的命令行程序和快捷方式随之增减。 |
| 运行 | 安装后的 GUI 成功渲染 PLY，命令行工具本机回环发出的 60 帧 NDI、50 帧电生理数据全部收到。 |
| 离线修复 | 删除测试用的原始安装 EXE，移走 Qt 平台插件、改坏同版本 HDF5 DLL 并删除桌面快捷方式。通过系统缓存的 EXE 点「修复」，两份文件的 SHA-256 均恢复，桌面入口重新出现。 |
| 升级 | 用仅供测试的 0.3.1 注入升级失败，0.3.0 恢复并能启动。正常升级保留了安装目录和已选组件；随后尝试降级，安装器返回 1638 并保留新版本。 |
| 卸载和重装 | 从缓存入口卸载后重新安装，再通过维护页点「卸载」。测试安装和快捷方式均已清理，预置在安装目录内的用户模型保留，用户和系统的全局 `PATH` 与测试前相同。 |

截图中的「无法设置文件安全，错误 5」来自普通权限 QA 副本在 D 盘清理 `Config.Msi` 回滚文件时的 Windows Installer 1926 提示。已将这个专用 QA 副本移到当前用户的应用数据卷。修正后的普通账户测试及最终 EXE 在 D 盘的整机实装均已通过，两组日志中都没有 1926 提示。测试未改动系统目录的权限。

本机已有兼容的 VC++ 运行库，安装器正确识别并跳过安装。全新系统缺少运行库时的首次离线安装、Windows 10 传统快速启动栏仍待相应系统实测。

## 首次安装

| 向导项目 | 安装行为 |
|---|---|
| 安装位置 | 默认安装到 `%ProgramFiles%\SimTransferRT`，供本机所有用户使用。可以浏览或输入其他本地目录，例如 `D:\医疗软件\SimTransferRT`。确认页显示最终绝对路径和所需空间，支持中文和空格。安装时按需请求管理员权限，日常使用普通账户。 |
| 主程序 | 必装。主界面、网络收发、模型预览和转换一起安装。Qt、VTK、HDF5、Qt 平台插件、`qt.conf` 及随附许可按发布目录布局部署。 |
| 命令行工具 | 可选，默认关闭。勾选后安装 `SimTransferCli.exe` 和 `SimRtProbe.exe`，开始菜单增加「SimTransferRT 命令行」。该窗口从用户可写的工作目录启动，仅在本次会话把安装目录的 `bin` 加入 `PATH`。 |
| 环境变量 | 使用端需要手动填写的环境变量为 **零**。安装和卸载均保持用户及系统的全局 `PATH` 原值。构建机上的 `QT_PREFIX`、`VS_BUILD_TOOLS` 由现有脚本使用；`VTK_DIR`、`HDF5_DIR`、`SIM_BOOST_ROOT` 属于构建配置。 |
| 快捷方式 | 默认创建所有用户的开始菜单入口。「创建公共桌面快捷方式」默认不勾选，可以在首次安装或维护页更改。主程序入口沿用项目现有的阿斯克勒庇俄斯之杖图标。 |
| 快速启动与任务栏 | 传统快速启动图标默认关闭。对仍使用传统 Quick Launch 工具栏的 Windows 10 用户，兼容选项可在发起安装的交互用户账户下创建专用快捷方式，并记录归属，供该用户撤销。Windows 11 默认桌面的完成页提供「打开程序，右键任务栏图标，选择固定到任务栏」的指引。微软将传统 Quick Launch 文件夹保留用于兼容，任务栏固定由用户选择。[Windows 任务栏说明](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar-extensions) · [微软的任务栏固定指引](https://support.microsoft.com/en-us/windows/experience/personalization/customize-the-taskbar-in-windows) |

Microsoft Visual C++ x64 运行库随安装器离线携带。检测到兼容且版本足够时跳过，缺少或过旧时运行微软原版安装程序，并处理需要重启的结果。卸载 SimTransferRT 时保留这份系统共享运行库。[微软运行库部署说明](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files?view=msvc-170) · [Qt 6.12 Windows 部署说明](https://doc.qt.io/qt-6.12/windows-deployment.html)

## 已安装时的操作

维护页顶部显示产品名称、已安装版本和路径，下面按参考图纵向排列三个带说明的操作。卸载进入独立的确认页。

| 操作 | 用户可预期的结果 |
|---|---|
| **修改** | 显示当前已选组件和桌面图标状态，只应用用户更改的选项。主程序保留在原位置。需要迁移安装目录时，保留数据卸载后，再在目标位置安装。 |
| **修复** | 按本版本和已选组件重装产品文件，恢复缺失或损坏的 EXE、DLL、插件、已选快捷方式及安装登记。默认使用本机缓存的完整安装源。若系统缓存损坏，可以重新运行完整的同版本安装 EXE。[Windows Installer 修复模式](https://learn.microsoft.com/en-us/windows/win32/msi/reinstallmode) |
| **卸载** | 列出将移除的程序和安装器创建的入口，提示会保留用户数据，然后请求确认。按安装清单删除，目录中用户另存的模型、导出文件和其他文件均予保留。 |

将 Windows 产品登记和版本作为判断依据。运行同版本安装包进入维护；发现旧版本时显示升级确认，继承原安装路径、组件及桌面图标选择；发现已装更新版本则保留当前版本并提示。只发现手动解压的旧目录时，提示另选新目录，以免误接管其中的文件。Windows「已安装的应用」中只登记一个 SimTransferRT 产品入口。

程序文件与业务数据分别管理。现有每用户的 `v2-runs` 收发报告、`model-conversions` 转换档案、`QSettings` 设置，以及用户自行指定的归档目录均在安装器管理的文件清单之外。维护期间如果程序文件正被占用，向导使用 Windows Installer 的文件占用提示。正在收发或转换的用户可以先结束任务，再关闭程序继续维护。

## 接入当前发布流程

1. 用 `scripts\package.cmd` 运行 Release 构建、CTest 和 `cmake --install`。V2 入口 `scripts\package-v2.cmd` 执行同一流程。每次从新的暂存目录收集发布文件，两个命令行工具均来自同一套 CMake 安装清单。打包输入只取产品文件，测试程序、开发 SDK 和本机模型留在构建机。
2. 采用 **WiX Burn + 一个带中文维护界面的 MSI**。外层 EXE 内嵌主 MSI 和官方运行库，内层 MSI 管理组件、目录、快捷方式和修复。采用 WiX 的内部界面引导程序，使安装和维护共用同一套界面。缓存内嵌文件完整的主 MSI，支持用户删除下载的安装包后离线维护。发布方应按实际使用核对所选 WiX 版本的维护费条款。[WiX 安装与维护界面](https://docs.firegiant.com/wix/schema/bal/wixinternaluibootstrapperapplication/) · [WiX 界面库](https://docs.firegiant.com/wix/tools/wixext/wixui/) · [工具使用条款](https://docs.firegiant.com/wix/osmf/)
3. EXE 和 MSI 使用同一产品版本，分别保持稳定的升级标识。产品文件有变化即递增可识别的发布版本。升级在 MSI 可回滚的事务内替换旧版，失败时恢复旧程序。用发布方代码签名证书给主 MSI、Burn 引擎和最终 EXE 签名并加时间戳，随 Release 记录最终文件的 SHA-256。[WiX 升级与回滚](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/) · [WiX 签名流程](https://docs.firegiant.com/wix/tools/signing/)

## 正式发布验收范围

| 场景 | 通过条件 |
|---|---|
| 干净系统离线安装 | 在无 Qt、VTK 和开发工具的 Windows 11 x64 上，分别测试默认目录和含中文、空格的自定义目录。覆盖运行库缺失与已有兼容新版。用普通账户启动 GUI，执行模型打开、转换回读及本机收发。复用 `tests/verify_model_deployment.ps1` 核对实际加载的 DLL 和插件路径。 |
| 快捷方式和工具选择 | 核对默认值及勾选后的结果。重复修改时入口不重复，取消工具后入口随之移除。系统和用户 `PATH` 与安装前一致。Windows 10 x64 的传统工具栏兼容项在相应系统上单独验收，并核对提升权限时的账户归属。 |
| 同版本维护 | 重开同版 EXE 后出现三个入口。从系统产品入口启动维护；删除原下载文件后，仍可用本机缓存修复。分别模拟缺少 `qwindows.dll`、同版本产品 DLL 内容损坏、已选快捷方式丢失，修复后程序可启动且模型可显示。 |
| 升级与回滚 | 用两个实际版本验证升级和阻止降级。在自定义目录升级并注入一次产品安装失败，检查旧版仍可启动、已有选项和档案可用。 |
| 卸载与重装 | 从维护页和 Windows 系统入口分别卸载。程序和产品登记清除，预置的用户模型、报告、设置及共享运行库保留；重新安装后可继续打开原有数据。 |
