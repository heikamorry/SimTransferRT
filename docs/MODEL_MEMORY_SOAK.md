# 天安门模型连续 12 轮内存复测

2026-11-25，在同一 Windows Release GUI 测试进程中，12 次加载、显示、转换、回读和卸载均成功。此次没有观察到整份模型逐轮滞留，也没有观察到卸载后进程内存持续攀升。

前两轮按预热处理。第 3～12 轮卸载后的进程专用提交量在 **744.0～762.3 MiB** 之间，第 12 轮比第 3 轮高 **0.77 MiB**。同期工作集在 **822.7～840.6 MiB** 之间，首尾下降 **15.27 MiB**。每轮都用不增加引用计数的 VTK 弱指针跟踪实际显示的 actor、mapper 和网格数据；12 轮卸载后，三者均已销毁。有限轮数无法排除更慢的小额泄漏或其他模型路径的问题。

## 测量方法

- 输入文件为 `Tiananmen_Gate_Detailed.ply`，212,485,676 字节，4,490,824 个顶点，7,017,756 个面。SHA-256 为 `f66ca4ce9076516ab5314bd942db084c958700ad20e3cf7b942b167f74bdab6c`，与历史测试一致。
- Windows 11 x64（build 26300），Qt 6.12、VTK 9.4.2、HDF5 1.14.6。测试程序通过实际 Qt 预览面板操作，使用 Intel(R) Graphics 渲染。测试进程 PID 为 14892。
- 每轮从文件重新加载，显示并拖动模型，再导出 VTP 和写入 HDF5。转换流程回读两种输出并与输入数据比对。每轮使用独立临时目录，完成后清理转换产物。
- 独立线程按 20 ms 目标间隔读取 Windows 进程计数器，每轮实际取得 432～490 个样本。表中为采样峰值，短于采样间隔的尖峰可能遗漏。卸载前释放本轮帧缓冲截图，卸载后让 GUI 继续处理事件 1.5 秒，再取工作集、专用提交量和对象存活状态。
- 进程占用包含 Qt、VTK、分配器和驱动相关开销。表中不能单独分离模型堆内存。[原始测量 JSON](model-verification/memory-soak-20261125.json) 保留字节数、每轮采样数、对象释放状态和 GPU 计数。逐轮峰值见 `cyclePeakWorkingSetBytes` 与 `cyclePeakPrivateBytes`；历史兼容字段 `peakWorkingSetBytes` 和 `peakAfterConvertBytes` 是进程启动以来的高水位。

## 复测命令

在仓库根目录的 CMD 中运行，第二个参数使用新的证据目录。最后一个参数指定在同一个进程内重复的轮数。

```bat
call scripts\env.cmd
cmake --build build\windows-v2-release --target SimModelGuiTests
build\windows-v2-release\SimModelGuiTests.exe build\windows-v2-release\tests\model-fixtures build\windows-v2-release\memory-rerun "%USERPROFILE%\Downloads\Tiananmen_Gate_Detailed.ply" 12
```
