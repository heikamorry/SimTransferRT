# NDI 发包抖动与双模块控件更新优化

本方案的验收场景是 Windows x64 Release、可见接收页、本机 IPv4 UDP 环回。NDI 使用 4 个模拟工具、60 Hz，EP 使用 204800 字节、50 Hz，两路同时运行，档位 1000 Mbit/s。

| 指标 | 宿主 600 秒基线最大值 | 违规数 / 观测数 | 每次观测的要求 |
| --- | ---: | ---: | --- |
| NDI 首发包间隔偏差 | 2773 µs | 5 / 35999 | < 1000 µs |
| 全流发包间隔偏差 | 2783 µs | 6 / 4325999 | < 1000 µs |
| NDI 收齐至控件数据更新 | 117674 µs | 601 / 36000 | ≤ 16667 µs，逐帧更新 |
| EP 收齐至控件数据更新 | 125762 µs | 353 / 30000 | ≤ 20000 µs，逐帧更新 |

基线取自 `build/validation-loopback-20261126-1116/host-final-600/joint.json`。发包指标使用本地发送开始时刻，参照原始调度计划。全流统计相邻包，包含跨模块间隔以及实际发生的重传和状态包。

## 针对发送线程交接

NDI 帧 17097、17098、17804 均准时采样，准备各耗时 27 µs。准备完成到开始发送分别等待 1731、2778、1562 µs。最慢一帧的发送调用另耗时 225 µs。已有证据支持先优化交接，对这几次等待的内核调度成因仍需独立观测。

候选只在没有待发包、接近已公布的 NDI 时隙时提前唤醒发送线程，并把可延期的统计快照移出该窗口。GUI 的“NDI 交接提前量”和 CLI 的 `--ndi-handoff-guard-us` 使用同一配置，0 关闭，最高 400 µs。提前量另受 NDI 周期的 1/32 限制，时隙后的检查窗口至多为提前量的一半。每次短等最多 25 µs，随后重新检查 EP、状态、反馈和停止条件。采样率、EP 分片与选包规则、重传策略和验收统计继续沿用原配置。

60 Hz、400 µs 时，完整窗口每秒覆盖至多 36 ms。实际代价应结合 `sender.ndi_handoff.brief_wait_wall_us` 和 `run.json` 的 `driver_cpu_seconds` 判断，前者包括短等期间可能发生的抢占，后者覆盖整个 GUI 测试进程。如果窗口内取帧增加但 NDI 违规次数、峰值没有可重复的改善，就没有依据继续增加提前量。若全流仍超限，先核对最坏相邻包所属模块和发送调用耗时，再决定是否调查 EP 分片路径。

同一新版在自动环境顺序运行两轮，每轮 60 秒。两路各完成 3600、3000 帧本地首传。该环境 UDP 接收为零，以下对照仅覆盖发送端。

| NDI 提前量 | NDI 发包最大偏差 | 全流最大偏差 | EP 发包最大偏差 | 整个测试进程 CPU 时间 |
| --- | ---: | ---: | ---: | ---: |
| 0 µs | 206 µs，0 次违规 | 921 µs，0 次违规 | 943 µs，0 次违规 | 19.27 s |
| 400 µs | 210 µs，0 次违规 | 989 µs，0 次违规 | 1096 µs，2 次违规 | 21.88 s |

400 µs 的设置在 2562 个窗口内都取到了对应帧，累计短等 0.510 s。两项目标峰值均未改善，EP 出现违规，故默认值保留 0。单次 A/B 不能单独判定 EP 峰值的成因。原始数据位于 `build/four-metric-20261126-120839/guard-0-60` 和 `guard-400-60`。

随后用 0 µs 在同一自动环境运行 600 秒。NDI 发包最大偏差为 550 µs（0/35999），全流为 2047 µs（10/4325999），EP 发包为 2048 µs（10/4289999）。NDI 和 EP 分别完成 36000、30000 帧的本地首传，最大耗时分别为 492、3844 µs，两路均无超时或未完成帧。采样最大偏差分别为 390、453 µs，两路均无跳采、丢队列或采样超限。该轮 GUI 接收了 0 帧，两个控件指标均为未测；这些数据不能用来计算相对宿主 600 秒基线的优化收益。详见 `build/four-metric-20261126-120839/automatic-600/joint.json`。

另用同版 Asio 异步 CLI 开启分片诊断 75 秒，保持快速队列、数据率和预算一致。这轮全流最坏相邻包是 EP 帧 332 的末片与 NDI 帧 399 的首片。它们分别比各自计划晚 1900、41 µs，因此实际相邻间隔比计划短 1859 µs。EP 帧 332 的 143 片从首次尝试到最后完成共 3640 µs，其中提交到观察本地完成累计 3413 µs，调用区间之间合计 227 µs。片 100、101 分别用时 609、438 µs。这次诊断定位到 EP 尾片累积滞后；未直接观测 600 秒运行中的每一对违规包。原始证据见 `build/four-metric-20261126-120839/gap-trace.json`。

独立 Release 进一步分开记录传输层提交返回和完成处理器观察时间，仅在启用分片诊断时增加计时。90 秒 CLI 诊断中，全流峰值为 937 µs，没有复现超标；最坏相邻包同样是 EP 末片与 NDI 首片。该轮最慢 EP 帧 3006 的 143 片共用 2646 µs，其中调用提交到返回合计 2399 µs，返回到观察完成合计 89 µs，片间合计 158 µs。报告见 `build/four-metric-20261126-120839/submit-trace.json`。现阶段应优先核对宿主超限帧的提交调用成本；本次数据不足以支持提高在途深度或修改重传策略。任何此类改动还需独立验证回调顺序、首传时限、重传和取消时的缓冲区寿命。

## 针对 GUI 排队

基线中 NDI、EP 等待 GUI 开始处理的最大值分别为 117598、125698 µs。单帧应用到控件的最大耗时分别为 275、181 µs。另一次可见接收页 30 秒诊断中，接收页刷新和 VTK 渲染分别记录到 47055、15900 µs 的峰值。

收齐的帧通过 Qt 高优先级事件唤醒 GUI。多帧可以共用一次唤醒，每帧依序写入控件并独立计时。统计、日志和可见模型预览由普通刷新处理，短时 BX 预览省去同步进度条重绘。接收队列保留容量限制和溢出计数。Qt 合成到换帧的耗时单独记录，以便和 VTK 渲染、控件更新区分。只有当后续报告显示单帧应用成为主要耗时，才值得继续替换表格组件或帧数据容器。

## 比较收益与回退

同一版本先用 0 和 400 µs 串行 A/B，保持窗口可见、输入相同。完整的宿主比较使用每轮 600 秒，调换顺序复测可以区分偶发系统负载和参数效果。若两档都通过，可用较小提前量继续对照，选择实际 CPU 成本较低的设置。若基线已通过的指标出现新违规、有效交付减少或峰值持续恶化，保留 0 并检查具体最坏帧。

核对两次报告中的完整帧数、最大值及违规数。最近宿主基线的 NDI/EP 采样抖动为 562/597 µs，首传最大耗时为 3030/2641 µs，EP 发包抖动为 863 µs。两路各完整交付 36000/30000 帧。比较文件会列出以往通过而本次未确认的项目。同一轮中，四项均通过、逐帧对账完整且既有指标保持通过，才构成本次工况的验收证据。

在仓库根目录的普通 PowerShell 运行下列命令。每轮使用独立目录。第一轮使用默认提前量。如果本地保留了历史基线，脚本会同时进行比较。第二轮用来独立评估 400 µs 的边际收益。

```powershell
$run = Join-Path 'build' ("timing-ab-" + (Get-Date -Format yyyyMMdd-HHmmss))
$before = 'build/validation-loopback-20261126-1116/host-final-600/joint.json'
$comparison = @()
if (Test-Path $before) { $comparison = @('--compare-to', $before) }
py -3 -B tools/run_release_loopback.py --basic-tests --visible --seconds 600 --ndi-handoff-guard-us 0 --output "$run/off" @comparison
if (Test-Path "$run/off/joint.json") {
    py -3 -B tools/run_release_loopback.py --visible --seconds 600 --ndi-handoff-guard-us 400 --output "$run/on" --compare-to "$run/off/joint.json"
}
```

## 交换间隔试验的 600 秒正式结果

开启 `SIM_GUI_IMMEDIATE_SWAP` 的候选在 `127.0.0.1` 运行了 600 秒，关闭分片追踪，NDI 交接提前量为 0 µs，Asio 操作复用关闭。NDI 36,000 帧、EP 30,000 帧全部完成首传、接收、消费和控件更新。全流发包偏差最大 428 µs，NDI 为 417 µs，EP 为 454 µs，三项均零超限。

NDI 收齐至控件更新最大 112,006 µs，62/36,000 帧超出 16,667 µs。EP 最大 116,788 µs，11/30,000 帧超出 20,000 µs。联合验收中的两项 GUI 指标均失败。随后加入的 EP 重复采样波形绘制优化需要使用包含该改动的构建单独长测。这一轮的程序哈希和验收明细分别保存在 `build/gui-swap-20261126/loopback-h9r54fi9/formal/run.json` 和同目录的 `joint.json`。
