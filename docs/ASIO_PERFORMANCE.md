# V2 Asio 对照结果（asio 分支）

## 测量口径

- Windows 11，MSVC 14.44 x64，Qt 6.12，Release，`SIM_MODEL_PREVIEW=OFF`。
- 独立 Python 接收桩 `tools/v2_receiver.py`，发送端与接收端同机回环。
- 负载：1 Gbps 档、EP 204800 字节 @50 Hz、NDI 4 tools @60 Hz、无状态流、无故障注入。
- 每轮 8 秒；发送端与接收端各自输出 JSON，使用同一 `run-id`。
- 指标定义沿用 `Engine`：首发完成时间从实际采样到最后一次本地发送完成；
  抖动为原始计划间隔的绝对偏差；`p999` 为 100 µs 分桶估计。

## 实测（2026-11-20，独立三轮）

| 指标（EP，模块 2） | Qt 同步（基线） | Asio 同步 | Asio 异步 |
|---|---:|---:|---:|
| built / 完成 / 超期 / 未完成 | 400 / 202 / 56 / 198 | 400 / 400 / 0 / 0 | 400 / 400 / 0 / 0 |
| 首发 P99 | 94,200 µs | 2,200 µs | 2,600 µs |
| 首发 P99.9 | 101,852 µs | 2,238 µs | 2,706 µs |
| 首发最大值 | 101,852 µs | 2,238 µs | 2,706 µs |
| 逐包间隔偏差最大值 | 18,792 µs | 618 µs | 928 µs |
| 采样间隔偏差最大值 | 428 µs | 797 µs | 593 µs |
| 发送错误 | 0 | 0 | 0 |
| 接收完成 / 消费 | 202 / 202 | 400 / 400 | 400 / 400 |

NDI（模块 1）：Qt 基线 299/480 完成、121 次超期；Asio 同步与异步均 480/480、0 超期，
P99.9 分别为 307 µs 与 316 µs。

Qt 结果重复出现约 100 ms 的首发最大值；把两边发送缓冲区统一到 4 MiB 后仍然存在，
说明不是 `SO_SNDBUF` 差异。该停顿的根因尚未定位，因此不能把全部差距都归因于
“Asio 比 Winsock 快”。可复现的事实是：在同一负载、同一接收桩、同一 4 MiB 缓冲下，
Asio 同步/异步路径没有出现该停顿，Qt 适配器稳定出现。

## 结论与限制

- 已证实：Asio 路径协议正确、计数完整、停止/取消可回收，12/12 CTest 通过。
- 已证实：本轮回环中 Asio 路径消除了 Qt 适配器观察到的长停顿。
- 未证实：该改善完全来自 Asio 本身；Qt 停顿的根因仍未隔离。
- 未验证：30 分钟长测、真实网卡双机、物理出线期限、GUI 接收器迁移后的对照。
- 异步路径当前逐包观察完成，没有流水线收益；其数值与同步路径接近，符合这一实现方式。
